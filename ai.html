浙大 + 联想提出 EM²Mem：多模态智能体的"事件中心记忆"方案，先对齐后检索颠覆传统范式

  • 时间：11月16日（mechlabs.cn 快讯）
  • 人物/机构：浙江大学、联想团队
  • 事件：联合提出多模态长期记忆方案 EM²Mem，核心思路是"先对齐后检索"——先把新输入与已有事件中心做语义对齐再检索，而非传统的"直接向量检索"；同时构建了 LightMem-Ego 系统作为验证平台，在召回率和效率上均有提升，为多模态 Agent 如何"记住并理解过往"提供了新范式
  • 数据：召回率与检索效率优于传统方案；LightMem-Ego 系统已构建
  • 关键名词：EM²Mem、事件中心记忆、多模态长期记忆、先对齐后检索、LightMem-Ego
💡 看点：Agent 的记忆管理从"存得下"进入"记得准"阶段——多模态上下文下传统 RAG 的召回衰减问题，靠"先对齐再检索"的范式切换来破。对做企业知识库+Agent 的团队，这直接关系到问答准确率和用户信任感。

Claude Code "以后不再询问"选项泄露数千条密钥：Apiiro 发现 GitHub 上 1122 份配置文件含敏感信息重点

  • 时间：11月8日 Apiiro 发布研究，11月11日–16日 36氪、ApriDog、Bregg 等持续跟进
  • 人物/机构：安全公司 Apiiro、GitGuardian；Anthropic（Claude Code 开发方）
  • 事件：安全公司 Apiiro 发现公开 GitHub 仓库中出现大量 Claude Code 的配置文件 .claude/settings.local.json，其中包含数据库密码、API Key、云凭证乃至超级管理员登录凭证；泄露根因是 Claude Code 中 "Yes, and don't ask again" 选项会将含敏感信息的完整命令明文写入本地配置文件，一旦开发者把该文件提交到 Git（虽有全局排除但容易被覆盖），密钥就公开了；GitGuardian 进一步分析发现涉及 23271 个公开仓库、31088 个独立密钥
  • 数据：Apiiro 检出 1122 份公开文件含 1379 个真实密钥；GitGuardian 扩展到 23271 仓库、31088 密钥
  • 关键名词：Claude Code、settings.local.json、密钥泄露、.gitignore 覆盖、安全漏洞
💡 看点：AI 编程助手的安全边界正在被"一键方便"击穿——用户为了少点几次确认，把密码和密钥明文交给了配置文件，而 Git 的排除规则在团队协作中极易被覆盖。对做企业内部开发规范的人，这是把"AI 工具密钥安全"纳入代码审查清单的紧急提醒，比之前关注的"提示词注入"更落地、风险更直接。
